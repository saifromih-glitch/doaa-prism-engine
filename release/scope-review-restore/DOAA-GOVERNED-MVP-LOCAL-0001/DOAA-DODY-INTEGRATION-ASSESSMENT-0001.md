# تقييم الاستفادة من دودي داخل مشروع دعاء

## الحكم

يمكن استخدام دودي كمرجع منهجي وتشغيلي أثناء إكمال دعاء، وليس كمكوّن يملك سلطة أعلى من دستور دعاء. عند التعارض، تسود حدود دعاء الأكثر تقييدًا.

## قواعد قابلة لإعادة الاستخدام

| القاعدة في دودي | طريقة الاستفادة داخل دعاء | التصنيف |
|---|---|---|
| افهم ثم خطط ثم نفذ ثم أثبت | تحويل كل توسعة إلى عقد وADR واختبارات وقبول | قابلة للدمج |
| فصل الحقائق والافتراضات والقرارات والاقتراحات | تحسين سجلات التدقيق وتقارير الدورة | قابلة للدمج |
| تحديد نطاق الملفات وخارج النطاق | منع التوسع غير المقصود أثناء البناء | قابلة للدمج |
| الدليل قبل ادعاء النجاح | إلزام كل نتيجة بعدد الاختبارات ونتائجها وما لم يُختبر | قابلة للدمج |
| بوابات المرور والمراجعة البشرية | دعم مسار الاقتراح ثم البوابة ثم التنفيذ الآمن | قابلة للدمج |
| سجل الحالة والرجوع | تحسين الاستئناف والتراجع والتوثيق | قابلة للدمج |

## ما لا يُنقل

لا تُنقل هوية دودي أو أي تعليمات عامة على أنها سلطة تنفيذية. لا يُسمح بالتعديل الذاتي، أو تشغيل الأوامر، أو الكتابة غير المصرح بها، أو النشر، أو كشف الأسرار، أو اعتبار نجاح الاختبارات المحدودة ضمانًا مطلقًا. ولا يُسمح باستخدام دودي لتجاوز العقود أو المراجعة البشرية في دعاء.

## قرار الدمج

يُستخدم الملف كمرجع تصميمي عند صياغة المهام والتقارير، وتُقتبس منه فقط قواعد العملية التي تتوافق مع دستور دعاء. لا يُضاف الملف إلى مسار التنفيذ، ولا يُقرأ كتعليمات تشغيلية من النموذج المحلي، ولا يتحول إلى صلاحية أو منفذ برمجي.

## الخطوة التالية الوحيدة

عند تثبيت الملف داخل المشروع، يُضاف إلى manifest بوصفه وثيقة مرجعية فقط، ثم يُعاد تشغيل القبول الكامل مع التحقق من عدم دخوله في مسار التنفيذ.
